## 2026-11-08 — 2단계(도로 건설)

### 완료한 것
- 도로망 로직(src/sim/network.ts): 노드·도로 구간, 왕복 2·4차로 직선, 교차점 자동 분할(십자·T자), 8m 노드 병합, 철거
- 기하 제약(rules.md 7항): 최소 길이 20m, 병합 반경 8m, 교차 최소 각도 30°, 교차로당 도로 최대 6개. 건설 전 `planRoad`로 가능 여부 계산
- 실행 취소/다시 실행(src/sim/editor.ts): 건설·철거·불러오기를 되돌릴 수 있음. 기록 최대 200개
- 저장/불러오기: IndexedDB 슬롯 3개 + JSON 파일 내보내기/가져오기. 저장 형식 번호 1, 잘못된 파일은 쉬운 메시지로 거부
- 화면: 도로 렌더, 미리보기(초록=가능, 빨강=불가+이유), 길이 표시, 철거 강조, 격자 스냅(20m)·각도 스냅(15°), 이어 그리기
- 조작: 왼쪽 클릭 시작·끝, 우클릭/Esc 취소, 단축키 R(2차로) T(4차로) X(철거) Ctrl+Z/Y, Space 일시정지. 일시정지 중에도 건설 가능
- 1단계의 기준 주황 상자는 교차로를 가려서 제거

### 확인한 방법
- 자동 테스트 42개 통과(도로 규칙, 경계값, 실행 취소, 저장 왕복, 결정론, 잘못된 파일)
- 실제 Chromium에서 실제 마우스 클릭으로 20항목 통과: 길이 표시, 건설, 십자 교차, 빨간 안내, 실행 취소/다시 실행, 슬롯 저장·불러오기, 철거, 불러오기 취소, 드래그가 건설로 오인되지 않음, 콘솔 오류 0건
- 스크린샷으로 4차로 폭, 초록/빨간 미리보기, 철거 강조 확인
- 성능 측정(임시 테스트): 도로 841개·노드 462개에서 미리보기 계산 0.32ms, 스냅샷 85KB

### 미확인·미해결(알려진 제한)
- 사용자 PC에서의 마우스 조작감(이동/회전/클릭 구분, 스냅 느낌)은 사용자 확인 필요
- 기존 도로의 끝점 위를 정확히 지나가는 긴 도로는 "노드와 너무 가까움"으로 거부됨(끝점에서 끝나게 나눠 건설해야 함)
- 철거 후 2개 도로만 이어진 이음 노드는 남음(모양은 같음, 합치기는 미구현)
- 실행 취소는 전체 스냅샷 방식. 아주 큰 도로망에서 메모리 사용이 늘 수 있음(현재 규모는 문제 없음)
- 저장 슬롯은 Chromium에서만 확인(다른 브라우저 미확인)
- 도로에 차량이 아직 없음(3단계에서 차선 그래프와 차량 주행)

## 2026-11-08 — 3단계(차선 그래프·차량 주행)

### 완료한 것
- 차선 그래프(src/sim/lanes.ts): 도로마다 방향별 차선(1번 = 진행 방향 오른쪽 맨 끝, 중앙선에서 가장 멈), 교차로 안 연결선(곡선), 막다른 끝 회차 연결선. 도로 ID 순서로 번호를 매겨 항상 같은 결과
- 경로 탐색(src/sim/route.ts): 출발 도로의 아무 차선 → 도착 도로의 아무 차선, 시간 기준 최단 경로. 연결 안 되면 "경로 없음"
- 차량 주행(src/sim/traffic.ts): 제한속도·곡선 속도·앞 구간 제한을 보고 가감속, 도착 지점에서 정지·제거, 막다른 끝에서 1초 정지 후 회차, 앞차와 안전거리 유지, 겹침 방지 안전망(개입 횟수 기록)
- 연속 투입(대수·간격), 자리가 막히면 대기·5분 초과 시 포기, 도로망이 바뀌면 차량 모두 제거
- 화면: 차량 상자(InstancedMesh, 움직이면 파랑·멈추면 주황, tick 사이 보간), "차량 투입(테스트)" 도구(V), "차량 제거", 디버그 표시(D): FPS·tick·차량 수·투입/도착/포기/경로없음·안전망 개입, 차선 중심선·연결선, 차선 ID 라벨, 차량 상태 라벨

### 확인한 방법
- 자동 테스트 60개 통과(차선 모양·번호, 연결 정합, 경로, 회차 1초 정지, 앞차 안전거리·겹침 0, 연속 투입, 교차로 통과 시 순간이동 없음, 경로 없음, 도로 변경 시 차량 제거, 결정론)
- 실제 Chromium 스모크 28항목 통과(마우스로 건설→차량 투입→10대 모두 교차로 통과·도착, 안전망 개입 0, 디버그 패널·라벨, 도로 수정 시 차량 제거, 콘솔 오류 0건)
- 스크린샷으로 차선선·회차 곡선·교차로 연결선, 차량 상자, 회차 대기 장면 확인
- 성능(임시 측정): 차량 780대에서 1 tick당 0.29ms(4배속에서도 약 2.4%)
- 검토 중 발견해 고친 문제: 디버그 체크박스와 패널의 id 중복(`debug` → `debugToggle`), 디버그 라벨이 차량을 가려 안 보임(라벨을 위로 띄움)

### 미확인·미해결(알려진 제한 — 대부분 4단계에서 해결)
- **교차로에서 서로 다른 방향 차량이 부딪히지 않고 겹쳐 지나간다**(충돌 지점 예약·우선순위는 4단계). 안전망은 같은 차선·같은 연결선의 앞차만 본다
- 앞차 간격 규칙은 임시 단순 규칙(제동거리 기반). IDM은 4단계
- 차선 변경 없음. 교차로에서는 모든 들어오는 차선이 다른 도로의 모든 나가는 차선에 연결됨(회전 방향별 차선 배정은 4단계 이후)
- 막다른 끝 회차 시 반대 차선 간격 확인 없음
- 도로를 고치면 달리던 차량이 전부 사라짐(삭제 처리 규칙은 6단계)
- 연결선 곡선은 베지어 근사. 아주 급한 각도에서 모양이 어색할 수 있음
- 교차로 안 최저 속도 15km/h 규칙 때문에 회차는 현실보다 빠르게 돈다
- 사용자 PC GPU에서의 실제 부드러움·보이는 모양은 미확인
- 차량은 단순 상자(승용차 1종)
- 성능은 교차로 계산이 없는 상태에서 잰 값. 4단계 후 다시 측정 필요
