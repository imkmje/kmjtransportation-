# 자동차 게임 세부 계획과 오케스트레이션 (승인됨 2026-11-20)

> 작성일: 2026-11-20. 설계는 `docs/car/design.md`. 이 문서는 "무엇을 어떤 순서로, 누구에게, 어떻게 검수하며" 만들지를 정한다.

## 1. 역할
| 누가 | 하는 일 |
|---|---|
| 사용자 | 방향 결정, 단계마다 배포 주소에서 눈 확인, PR 병합 |
| 오케스트레이터(이 세션) | 설계·수치 결정, 작업 지시서 작성, 결과 검수(코드·검사 결과·화면 캡처 확인), 사용자 보고 |
| 코더(Opus 5.5 하위 에이전트) | 지시서 1장 = 작업 1개 구현 + 테스트 작성 |
| 잡무 담당(하위 모델 에이전트) | 커밋·푸시, 검사 실행, PR 만들기·병합, 문서 정리 |

**운영 방식 변경(사용자 지시 2026-11-21)**: 작은 수정(한두 군데 고치는 버그·문구·표시 오류)은 역할을 나누지 않고 한 에이전트가 코딩·검사·커밋을 한 번에 처리한다. 모델은 오케스트레이터가 작업 수준에 따라 Opus 또는 Sonnet으로 정한다(Sonnet: 문구·표시 오류·원인이 분명한 수정·검사 맞추기·문서 / Opus: 규칙·균형·여러 파일에 걸친 기능·원인을 찾아야 하는 버그·3D). 큰 작업의 코더도 자기 작업분을 직접 커밋·푸시한다. 배포(검사·PR·병합)는 몇 판을 묶어서 했으나, 사용자 지시(2026-11-21)로 버전이 오를 때마다 배포한다. 급한 버그는 묶음을 기다리지 않는다. 버전과 변경 이력은 판마다 따로 남긴다.

## 2. 진행 규칙
1. **한 번에 한 단계**. 단계가 끝나면 배포 주소와 확인 포인트를 알리고 멈춘다.
2. 작업 지시서에는 항상 넣는다: 목표, 읽을 문서 절(예: design 6·8장), 만들 파일, 공개 함수 시그니처, 수용 기준(테스트 이름), 금지 사항(sim에서 Math.random·DOM 금지, 수치는 config에).
3. sim 작업은 **순서대로**(타입을 공유하므로). render와 ui는 sim 인터페이스가 고정된 뒤 **동시에**(작업 폴더 분리) 진행할 수 있다.
4. 검사는 잡무 담당(하위 모델)이 실행하고, 오케스트레이터가 그 출력 원문과 캡처를 읽어 확인한 것만 '확인'으로 기록한다.
5. 설계에 없는 것을 코더가 임의로 정하지 않는다. 막히면 질문으로 돌려보내고, 오케스트레이터가 정하거나 사용자에게 묻는다.
6. 커밋은 작업 단위. 버전은 `car/src/version.ts`, 이력은 `docs/car/CHANGELOG.md`.
7. 교통 게임·에어 게임 파일은 건드리지 않는다(예외: `vite.config.ts`, `package.json` 스크립트, 배포 설정에 car 추가).
8. **PR과 병합(사용자 지시 2026-11-20)**: 단계가 끝나 검수를 마치면 잡무 담당이 PR을 만들고, **자동 검사(테스트·빌드)가 통과하면 병합**한다(오케스트레이터가 지시). 검사가 실패하면 병합하지 않고 원인을 고친다. 병합 뒤에는 배포 주소와 확인 포인트를 사용자에게 알린다.
9. **(운영 방식 변경 2026-11-21로 대체됨)** **잡무 위임(사용자 지시 2026-11-20)**: 커밋·푸시, 검사 실행(테스트·타입 검사·스모크), PR 만들기·병합, 문서 정리(progress.md, CHANGELOG.md 등)는 오케스트레이터가 직접 하지 않고 **하위 모델 에이전트**에게 맡긴다. 오케스트레이터는 무엇을 기록·확인할지 지시하고, 돌아온 결과(검사 출력 원문, 캡처)를 읽어 판단한다. 코딩은 Opus 5.5, 설계·판단·사용자 보고는 오케스트레이터가 맡는다.
10. **연속 진행(사용자 지시 2026-11-20)**: 3단계 → 4단계 → 5단계는 단계 사이에 멈추지 않고 이어서 진행한다. 단계마다 검사가 통과하면 병합하고 확인 포인트를 사용자에게 알린다.

11. **운영 방식 변경(사용자 지시 2026-11-21)**: 위 1장의 "운영 방식 변경"을 따른다. 작은 수정은 한 에이전트가 처리하고, 큰 작업의 코더도 직접 커밋·푸시하며, 배포는 몇 판을 묶어서 한다. 4·9번의 역할 나눔은 이 항목으로 대체된다.

## 3. 단계
재미를 일찍 확인하려고 **얇게 한 바퀴 → 살 붙이기** 순서로 간다.

### 1단계 — 한 바퀴 돌기 (0.1.0) : "차 한 대를 만들어 팔아 본다"
| 작업 | 내용 | 수용 기준 |
|---|---|---|
| C1 골격 | `car/` 폴더, vite 입력, 빈 페이지, version, 스모크 스크립트 | `/car/` 로드, 콘솔 오류 0 |
| C2 sim 기초 | types, rng, time(주·월·연), game(명령 기록·toJSON) | 결정론·저장 왕복 테스트 |
| C3 차와 개발 | 5.1~5.3, 6장(설계·시험·결함). 차체 3종·가솔린만 | 보정 목표(1970년 등급 4~5), 결함 규칙 테스트 |
| C4 판매 | 7.3 공식, 국내만, 경쟁사 3곳 고정값, 월 정산, 9.4 재무 기초·파산 | 가격↑ → 판매↓, 등급↑ → 판매↑, 파산 테스트 |
| C5 3D | 데모 `buildCar`를 TS·three 0.187로 이식, 무대, 평면 대체 | 차체 3종 캡처, 생성 30ms 이하 |
| C6 화면 | 상단바, 차고, 신차 기획, 개발 진행, 출시, 리뷰(평론가 4명), 월 보고, 저장 칸 | Playwright로 신차 1대 출시까지 |
사용자 확인: 차를 만들어 파는 한 바퀴가 재미있는가, 3D와 화면 스타일이 마음에 드는가.

### 2단계 — 차종의 일생 (0.2.0) : 페이스리프트·풀체인지 (완료 2026-11-20, 0.2.0)
| 작업 | 내용 | 수용 기준 |
|---|---|---|
| C7 lifecycle | 8장 전부(차종·세대·판 구조, 리프트·체인지 규칙, 차종 자산, 전작 비교, 재구매, 8.6 단종·부활) | 8장 규칙별 테스트, 저장 형식 2 + 형식 1 변환 |
| C8 얼굴·차대 값 | 14장의 차대/얼굴 분리, 후보 3개 생성, 시드 재현 | 같은 시드 = 같은 모양, 리프트는 옆모습 윤곽 불변 |
| C9 화면 | **신차 기획 첫 화면의 선택(새 차종 / 다음 세대 / 페이스리프트, 설계 8.7)**, 차종 카드(수명 막대·조언·버튼), 리프트 비교 화면, 체인지 흐름, 차종 계보 | Playwright: 출시 → 리프트 → 체인지 |
| C10 봇 | 16장 균형 봇 중 방치·신중·리프트 안 함 | "리프트 안 함"이 신중보다 불리함을 수치로 확인 |
사용자 확인: 리프트·체인지가 "하고 싶은 선택"으로 느껴지는가, 세대가 바뀔 때 차 모양 변화가 보이는가.

### 3단계 — 회사 (0.3.0) (완료 2026-11-20, 0.3.0)
직원(채용·교육·컨디션·배치), 본사 등급, 공장(증설·라인·배분), 대출, 동시 개발. 화면: 회사 탭.

### 4단계 — 시대 (0.4.0) (완료 2026-11-20, 0.4.0)
연구(기술 40개), 차체 10종·동력 4종·옵션 전체, 고정 사건 13개 + 무작위 사건, 시대 스타일 4종, 궁합과 조합 노트.

### 4.5단계 — 전반 다듬기 (0.5.0) (완료 2026-11-21, 0.5.0)
차 3D 결함 수정과 디자인 다양화, 사운드, 화면 버그·UX, 균형 재점검. 5단계 전에 둔다(2026-11-21).

### 5단계 — 세계와 경쟁 (후보로 옮김)
지역 4곳, 경쟁사 6곳 규칙(대응 신차·히트작·리프트 주기), 시장 지도 화면, 유행. 아래 "업데이트 후보(보류)"의 세계와 경쟁으로 옮겼다.

### 6단계 — 오래 하는 이유 (후보로 옮김)
시상식, 업적, 회사 칭호, 기록 화면 전체, 신문 기사 문구 확충, 소리. 목표와 보상은 아래 후보 절로, 신문 기사는 0.10.0으로 옮겼다.

### 7단계 — 다듬기 → 1.0.0 (0.10.0 이후, 일부는 후보 절과 겹침)
60년 봇 5종 균형 조정, 처음 하는 사람용 안내(첫 차까지 힌트), 성능(아이패드), 자동 저장, 파일 내보내기·가져오기, 도움말.

### 0.6.0 완료 (2026-11-21)
페이스리프트 옵션 버그 수정, 직원 일괄 교육·휴식, SUV 소·중·대 구분.

### 이후 일정 (2026-11-21)
- **0.7.0 임원** (완료 2026-11-21, 0.7.0. 사용자 지시로 0.8.0과 묶지 않고 단독 배포): 임원 6자리(인사·기획·재무·생산·연구소장·시장 조사), 임명·채용 둘 다. 본사 등급별 자리 수 1/2/4/5/6. 보고함에 월 결산 때 임원별 최대 2건 제안. 위임: 자동 휴식·자동 교육·자동 연구·생산 배분. 교체 고용 제안은 사용자 승인 뒤 예약하고, 개발 중인 직원은 개발이 끝난 뒤 진행한다. 승인한 기준 이상의 후보면 재승인 없이 진행하며 잠재력은 가리지 않는다. 그 밖에 할 일 목록과 다음 사건까지 넘기기.
- **0.8.0 편의 묶음** (완료 2026-11-21, 0.8.0): 전작 그대로 다음 세대 기획, 기획 프리셋, 빠른 기획, 자동 가격 유지와 최고 이익 가격, 직원 표 정렬·필터, 되돌리기(같은 주 직전 조작 하나, 출시·개발 시작 제외), 자동 저장 간격, 연 보고서.
- **0.9.0 화면 개편 (완료 2026-11-21)**: 무대 축소·패널 확대, 차고 첫 화면에 전 차종 요약 표와 내 차 비교, 연구·재무를 큰 메뉴로, 상단 바에 지난달 손익, 월 결산 펼쳐 보기. 배포 전에 캡처를 사용자에게 먼저 보여 준다.
- **0.10.0 정보와 수습 수단 (완료 2026-11-21)**: 차종별 손익 계산서, 판매 부진 원인 표시, 직원 성장 기록, 10년마다 신문 머리기사, 실패한 차의 수습(긴급 개선·가격 인하 판매).
- **배포 묶음**: 0.7.0+0.8.0, 0.9.0+0.10.0.
- **1.0.0 (완료 2026-11-22)**: 0.11.0(밸런스: 평판 상한 없음, 옵션 값, 동력 가산, 공장 6·7등급, 개발비 시대 상승, 경쟁사의 대응), 0.12.0(화면 정리: 설정·알림·할 일 서랍·차고 일괄 조작·재무·명예의 전당), 0.13.0(그래픽: 외관 후보 6개·직접 고르기·2030년대 스타일·출시 공개 장면·시대 분위기·사무실)을 사용자 지시로 묶어 1.0.0으로 올렸다. 저장 형식 4.

### 이후 계획 (2026-11-22 다시 씀)
**운영**: 버전이 오를 때마다 배포한다(사용자 지시 2026-11-21. 이전의 '묶어서 배포'를 대체).
**균형 원칙(사용자 지시)**: "새 기능은 쓰면 이득이 되게, 돈이 넘치면 기능을 약하게 하지 말고 쓸 곳을 더한다. 지키는 선은 초반에 파산하지 않는 것과 숫자가 무의미해질 만큼 폭주하지 않는 것."

- **1.1.0 옵션 개편 (완료 2026-11-22, 1.1.0)**: 장비마다 안 넣음 / 선택 사양 / 기본 장비, 옵션 칸 수 제한 제거, 시대의 기대(차급·연도별 기대 장비, 빠지면 감점·앞서면 가점), 추천 구성 자동 선택. 저장 형식 5.
- **1.2.0 후반 내용 (완료 2026-11-22, 1.2.0)**: 전기차 시대(배터리 용량·주행 거리·충전 속도·전용 플랫폼·배터리 자체 생산), 2040년 이후 가상 기술과 사건(2060년쯤까지).
- **1.3.0 차 만들기 (완료 2026-11-22, 1.3.0)**: 추가로 세대교체 위임(기획 임원), 출시 화면 유지, 알림 유형 선택도 넣었다.  개발 중 직원 성과(항상 긍정적, 고르기 없이 자동 적용, 균형에서 상쇄하지 않는 순수 이득, 직원 능력이 높을수록 자주·크게), 파생 모델(왜건·쿠페·고성능판·전기차판, 특색 뚜렷, 이름 변경 가능, 기본 제안 "A EV" 식), 평론가별 시승기.
- **1.4.0 인사 임원 자동 채용·해고, 용어 위임 (완료 2026-11-23, 1.4.0)**: 인사 임원 위임에 자동 채용·자동 해고 추가(둘 다 켜면 교체 고용 제안 없음), 화면 문구 "맡기기·맡김"을 "위임"으로.
