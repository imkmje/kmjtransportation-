## 0.3.0 — 2026-11-20 (저장 형식 3, 형식 1·2 자동 변환)
### 추가
- 직원: 채용 공고 3단계(후보 3명 중 선택), 해고(퇴직금), 교육(능력 +1~3, 연 1회), 휴식, 컨디션, 성장 한계(잠재력), 영업 직원(차가 더 빨리 알려지고 법인 판매 증가)
- 본사 등급 1~5(창고 공장 → 글로벌 본사): 정원 4/8/12/16/20명, 동시에 개발할 수 있는 차 1/1/2/2/3대, 옵션 칸 2/2/3/4/4
- 공장 등급 1~5: 월 생산 300/1,000/3,000/8,000/20,000대, 생산 라인 1/2/3/5/8개, 증설 공사 6개월, 차종별 생산 배분(자동/직접), 못 판 주문 표시
- 신차 기획에서 "누가 만들까요?" 팀 고르기, 차 여러 대 동시 개발과 전환
- 회사 탭을 재무 / 직원 / 본사 / 공장 네 화면으로 나눔
### 바뀜
- 개발 탭 배치: 사무실을 위쪽에 가로로 넓게, 진행·결함·주간 기록 패널은 아래에 나란히. 사무실은 본사 등급에 따라 넓어지고, 화면 밖에서 일하는 사람은 가장자리 버튼("시험실 ▸ 2명")으로 찾아감
- 균형(봇 측정으로 조정): 팀이 4명을 넘으면 한 사람의 기여가 줄어듦 / 경쟁사가 해마다 강해짐(1986년쯤 최대) / 시대 기준 상승 연 3.5% → 4.5% / 기준가보다 비싸게 팔면 판매가 훨씬 빨리 줄어듦 / 공장 건설비 2~5등급 17 / 260 / 2,200 / 7,000억, 유지비 1.9 / 5.2 / 18.6 / 52.5억, 원가 절감 1 / 2 / 3 / 4% / 페이스리프트 비용은 개발비의 40% / 가장 좋은 채용 공고는 평판 40 이상
- 0.2.0의 "공장이 300대로 고정이라 주문이 넘치고 가격을 올리면 돈이 폭발" 문제 해결(가격만 올리는 전략 ÷ 정상 운영: 약 14배 → 1.06배, 20년 차 주문 ÷ 생산 한도: 16배 → 1.6배)
### 확인한 것
- 타입 검사 오류 0, 전체 테스트 77개 파일 통과·1개 건너뜀(763개 통과·1개 건너뜀), car 테스트 8개 파일 132개 통과, 브라우저 점검(`npm run smoke:car`) 151항목 통과·콘솔 오류 0건
- 봇 측정(코더 측정, 시드 20개, 30년): 공장 등급 중앙값 10년 1 / 20년 3 / 30년 4, 20년 현금 중앙값 939억, 내는 차의 등급 10년 6.4 / 20년 6.9, 페이스리프트 1회의 이익은 비용의 약 2.6배, 공장을 키운 쪽이 안 키운 쪽의 약 2.9배
### 알려진 문제(미확인·미해결)
- 균형이 계수에 아주 민감하다(시대 기준 상승률을 4.5% → 4.2%로만 바꿔도 결과가 크게 달라짐). 4단계에서 연구·사건이 들어오면 다시 맞춰야 한다
- 봇 기준으로 목표에서 벗어난 값: 10년 차 현금 중앙값 19억(목표 30~200억, 초반이 빡빡할 수 있음), 30년 차 차 등급 4.4(목표 4.5~7), 20년 차 주문 ÷ 한도 1.6(목표 0.7~1.5), 페이스리프트를 쓰는 쪽 ÷ 안 쓰는 쪽 1.11(목표 1.15~1.6)
- 사람이 한 플레이 느낌(난이도·재미)은 미확인
- 회사 탭 등에서 알림이 왼쪽 아래에 여러 개 쌓여 직원 표 아래쪽을 잠깐 가린다
- 차고 카드에 조언 줄과 주문 상황 줄이 비슷한 말을 두 번 한다
- 페이스리프트 예상은 고른 팀이 아니라 쉬는 직원 전원 기준으로 계산된다
- 재무 화면의 본사·공장 유지비 구분은 지금 등급 기준이라 승급한 달에는 조금 다를 수 있다
- 실제 아이패드·갤럭시 탭에서의 속도와 터치 손맛 미확인
- 연구, 차체·동력·옵션 확대, 시대 사건, 수출은 아직 없다(4~5단계)

## 0.2.0 — 2026-11-20 (저장 형식 2, 형식 1 자동 변환)
### 추가
- 페이스리프트(부분변경): 출시 18개월 뒤부터, 세대당 1회. 새 얼굴 후보 3개 중 선택, 옵션·동력 단계 갱신. 비용은 그 세대 개발비의 35%
- 풀체인지(세대교체): 출시 36개월 뒤 또는 단종 상태에서. 이름값(차종 자산) 승계, 전작 비교 평론, 기존 고객 재구매, 전 세대는 출시 달 말 단종
- 신차 기획 첫 화면에서 새 차종 / 다음 세대 / 손보기 선택, 안 되는 선택은 이유와 남은 개월 표시
- 모양 고르기: 옆모습 후보 3개 + 얼굴 후보 3개(그림과 한 줄 설명). 시대 스타일 4종(1970·1990·2010·2020년대)
- 기록 탭의 차종 계보(세대별 사진·평론·판매·단종 시점)
- 개발 탭의 사무실 장면: 실제 사무실 같은 쿼터뷰, 직원이 걸어 다니고 그 주에 쌓은 점수가 머리 위에 뜸. 핀치로 확대·축소, 끌어서 이동, 두 번 톡으로 원위치, 사람을 누르면 이름·직무·컨디션
- 차를 출시할 때마다 참여 직원 능력 +1~2(상한 60, 3단계 전 임시)
### 바뀜
- 신차 기획·출시 화면: 아래에 붙어 있던 버튼을 없애고 내용 맨 끝의 버튼 줄로 옮김(마지막 단계에 [개발 시작], 출시 화면 끝에 요약과 [출시하기])
- 시장 규모가 해마다 계단식으로 뛰던 것을 달마다 매끄럽게 변하도록 수정(0.1.0의 "1971년 1월 3배 점프" 해결)
- 폰에서 알림이 맨 아래 버튼을 가리지 않게 위쪽에 표시
- 균형 수치: 페이스리프트 수명 되돌림 60%(늦으면 80%), 디자인 상승 한도 +10%, 인지도 +0.06, 시제차 비용 주당 5,800만원, 시장 규모 배수 2.1
### 확인한 것
- car 테스트 92개, 전체 723개 통과(1개 건너뜀), 타입 검사 오류 0, 브라우저 점검 107항목 통과
- 봇 측정(코더 측정, 시드 20개 × 20년): 이름을 잇는 전략이 매번 새 이름보다 현금 중앙값이 약 2배(499억 대 246억), 페이스리프트 1회의 추가 이익은 비용의 약 2.6배
### 알려진 문제(미확인·미해결)
- **공장이 월 300대로 고정**이라 1970년대 후반부터 주문이 생산 한도의 2~10배로 넘친다. 그래서 페이스리프트를 써도 더 팔 수 없고(봇 기준 +2%), 가격을 올리면 돈이 지나치게 빨리 불어난다. 3단계(공장 증설·직원 채용)에서 고친다
- 실제 아이패드·갤럭시 탭에서의 속도, 핀치·끌기 손맛, 사파리에서 핀치 때 페이지가 확대되지 않는지 미확인(터치 입력을 흉내 낸 자동 확인만 함)
- 사무실: 직원이 8명 이상이면 기본 화면에서 사람이 작고(화면 높이의 약 8%) 일하는 구역 가장자리가 잘린다. 시험 단계에서는 차가 있는 곳까지 넣느라 멀리서 본다. 개발 탭 배치와 함께 3단계에서 검토
- 풀체인지 때 차대 변화 폭이 작아 "확 바뀐" 느낌이 약할 수 있다. 2010년대와 2020년대 스타일이 비슷하다
- 페이스리프트 개발 화면의 능력치는 지금 판매 중인 판의 값을 보여 준다(개발 중 미리보기 없음)
- 균형은 봇 측정 기준이며 사람이 한 플레이 느낌은 미확인. 결과가 양극단으로 갈린다(잘되면 수백억, 아니면 파산)
- 직원 채용, 공장 증설, 연구, 시대 사건, 수출은 아직 없다(3~5단계)

## 0.1.0 — 2026-11-20 (저장 형식 1) — 배포됨(PR 139)
### 추가
- 차 한 대의 한 바퀴: 신차 기획(차체 3종, 고객층 6, 동력 등급 3, 옵션, 개발 방향 10점, 예산·기간, 색) → 개발(설계·시험·결함) → 출시(가격·마케팅·색·휠) → 평론가 4명 리뷰와 신문 → 월 판매 → 가격·마케팅 조정 → 단종 → 다음 차

- 저장 칸 3 + 매월 자동 저장 + 파일 내보내기·가져오기, 파산과 구제 금융(1회)
- 결함 경고(개발·출시 화면)와 출시 전 확인 창
### 확인한 것
