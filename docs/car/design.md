> 상태: **승인됨(사용자 2026-11-20).** 1단계 구현 진행 중.
> 작성일: 2026-11-20 (Asia/Seoul). 수치는 모두 **초기 후보값**이다(봇 테스트와 플레이로 조정). 실제 통계·실제 차량 제원이 아니다.

## 0. 확정된 결정 (사용자 2026-11-20)
1. 코드는 이 저장소의 `car/` 폴더에 둔다(에어 게임의 `airline/`과 같은 방식). 배포 주소는 `/car/`.
2. 시대: **1970년 창업 → 2030년대**까지 사건·기술이 준비되고, 그 뒤에도 계속 플레이할 수 있다.
3. 한 판 구조: **끝 없는 자유 플레이**(엔딩 없음). 파산은 있다.
4. 차 설계 깊이: **가볍게**(차체·동력·옵션 선택 + 개발 방향 점수 배분). 공학 지식이 필요 없어야 한다.
5. 경쟁사 이름은 실제 브랜드를 살짝 비튼 패러디(도요다, 현다이, 비엠브이, 테슬러, 포티 …). 로고 도형은 새로 그린다.
6. 그래픽: 에어 게임의 깔끔한 UI 뼈대 + **3D 스튜디오**(곡면 차체, 회전 무대). 기준 데모는 `docs/car/demo/car-studio.html`.
7. **페이스리프트(부분변경)와 풀체인지(세대교체)**를 구현한다(8장).
9. **회사 이름은 새 게임을 시작할 때 플레이어가 정한다**(빈칸이면 "새 회사"). 게임 이름은 미정이라 가칭 "카 컴퍼니"를 쓴다. (2026-11-20 추가)
10. 메인 화면은 **3D 차고**. (2026-11-20 추가)
11. 기준 기기는 **아이패드와 갤럭시 탭 울트라**(큰 태블릿, 가로 화면 우선, 터치). 폰·PC에서도 깨지지 않게 한다. (2026-11-20 추가)
12. **단종**을 플레이어가 직접 할 수 있다(8.6). (2026-11-20 추가)
8. 역할: 설계·세부 계획·검수는 오케스트레이터, 코딩은 Opus 5.5 하위 에이전트(`docs/car/plan.md`).
13. **커밋·검사 실행·PR·문서 정리는 하위 모델에 맡기고, 검사가 통과하면 병합까지 진행한다.** 사용자는 단계가 끝날 때 배포 주소에서 확인한다. (2026-11-20 추가)

15. 새 게임에서 난이도(쉬움·보통·어려움)를 고른다. 기본은 쉬움. (2026-11-20 추가)

## 1. 한 줄 요약
1970년, 직원 4명의 작은 공장에서 시작해 차를 기획·개발·출시하고, 번 돈으로 사람·공장·기술에 재투자하며 시대 변화(오일쇼크, SUV 유행, 전기차 전환)를 헤쳐 나간다.

## 2. 핵심 반복 (한 바퀴 = 게임 시간 약 6~12개월, 실제 3~8분)
1. **기획**: 차체 종류 × 주 고객층을 고른다(궁합이 있다).
2. **개발**: 동력·옵션을 고르고 개발 방향 점수를 배분한다. 직원이 매주 점수를 쌓고 결함도 함께 쌓인다. 시험 단계에서 결함을 줄이다가 "출시" 시점을 직접 정한다.
3. **출시**: 가격·마케팅·판매 지역을 정한다. 평론가 4명의 점수가 나온다.
4. **판매**: 매달 판매량·이익이 들어온다. 차는 나이를 먹으며 덜 팔린다.
5. **재투자**: 직원 채용·교육, 공장 확장, 연구, 그리고 기존 차의 **페이스리프트 / 풀체인지**.

재미의 축: (a) 조합 발견 (b) "지금 낼까, 더 다듬을까" (c) 세대를 이어 가는 내 차종의 역사 (d) 시대 변화에 대한 대응.

## 3. 범위
**포함(1.0.0)**: 2장의 반복 전체, 직원, 공장, 연구, 국내 시장 + 수출 3개 지역, 경쟁사 6곳(규칙 기반), 시대 사건, 평론·시상식·업적, 페이스리프트·풀체인지, 3D 차량 생성, 저장·불러오기, 균형 점검 봇.
**제외**: 주식·인수합병, 딜러망 세부 관리, 모터스포츠, 부품 공급망, 노사 협상 세부, 멀티플레이, 엔진 내부 설계.

## 4. 시간
- 1 tick = **1주**. 4주 = 1개월, 48주 = 1년. 시작 1970년 1월 1주.
- 배속: 일시정지 / 멈춤 / 보통(1주 = 3초) / 빠름(1주 = 1.5초) / 아주 빠름(1주 = 0.75초). (2026-11-21 0.4.2: 기본 1.5초 → 3초) 결정 창이 뜨면 자동 일시정지. 탭이 숨겨지면 일시정지.
- 판매·비용 정산은 **월말**, 시상식과 연간 보고는 **12월 4주**.
- 결정론: 같은 시드 + 같은 입력 = 같은 결과. `car/src/sim`에서 Math.random·Date 금지, 시드 난수만 사용. 반복 순서는 ID 순.
- 교통 게임의 "20 tick/s" 규칙은 적용하지 않는다(주 단위 경영 게임). 이유: 물리 시뮬레이션이 없다.
- 물가 상승은 넣지 않는다. 모든 금액은 "지금 돈 가치" 기준(단위: 만원, 화면에는 억 병기).

## 5. 차

### 5.1 능력치 5개
성능(P) · 연비(E) · 실용(U) · 디자인(D) · 품질(Q).
- 내부값은 원점수(상한 없음). 화면에는 **시대 평균 대비 등급 0~10**으로 보여 준다: `표시 = 5 × 원점수 / 기준(연도)`, 10에서 자름.
- `기준(연도)`는 1970~80년 해마다 4.5%, 1980~90년 3%, 1990~2010년 2.5%, 2010년 이후 1.5% 상승을 이어 곱한 값(시작 100, 2010년부터 1.5%는 1.0.0). 즉 가만히 있으면 내 차는 해마다 그만큼 낡는다. (2026-11-21 0.4.2: 구간별 상승률로 변경)

동력 등급(보급형/표준/고급)의 원가 가산은 0/7/16%다. (2026-11-21 0.5.1: 10/22% → 7/16%)

동력 점수 = `40 × 1.25^(단계 − 1)`(2026-11-21 0.4.2: 1.22 → 1.25)을 P : E 비율로 나눠 준다.

동력 등급(보급형/표준/고급)은 연구한 최신 단계에서 −2/−1/0 단계를 고르는 것이다. 해금 때 시작 단계: 가솔린 3, 디젤 5, 하이브리드 7, 전기 7. 전기차 수요에는 충전소 보급률(2012년 5%에서 해마다 상승)이 곱해진다. (2026-11-20 조정)

### 5.4 옵션과 장비 (1.1.0 개편: 3단계, 칸 수 제한 없음)
연구로 해금된다. 각 옵션은 U/D/Q 점수와 원가를 더한다. 옵션은 16개(12개 + 가죽 시트, 열선 시트, 선루프, 사륜구동)다. (2026-11-20 조정) 예: 라디오(1970), 에어컨(1975), 파워 스티어링(1980), 자동 변속기(1983), ABS(1988), 에어백(1992), 내비게이션(1999), 후방 카메라(2006), 스마트 키(2008), 주행 보조(2015), 대형 화면(2018), 자율주행 2단계(2023).
**장비 3단계(1.1.0)**: 장비마다 안 넣음 / 선택 사양 / 기본 장비. 옵션 칸 수 제한은 없다(본사 등급의 옵션 칸 보상 삭제, 9.2). 규제 의무 장비(11.3)는 늘 기본 장비다. 구현은 `sim/equip.ts`, 수치는 config `equip`.
- 기본 장비: 원가·능력치 효과 전부, 옵션 값(손님이 쳐 주는 값)이 차의 기준가에 더해진다.
- 선택 사양: 차 가격은 그대로. 선택률 = 기대 단계 기본값(드묾 0.15 / 흔해지는 중 0.4 / 기대됨 0.75) x 고객층 궁합(맞으면 x1.3, 아니면 x0.5) x 대형의 드문 장비(x1.5), 0.03~0.9로 자른다. 선택한 손님은 추가 요금(원가 x 1.4)을 내고, 대당 평균 이익 = 선택률 x (요금 - 원가). 능력치 효과 = 0.3 + 0.5 x 선택률.
- **시대의 기대**: 장비 x 차급 x 연도. 차급은 차체 기준가 2,000만 미만 소형, 4,500만 미만 중형, 그 위 대형. 연도 표(`options.json expect`)는 [흔해지는 해, 기대되는 해]이며 그 전은 '드묾'. 기대 장비가 없으면 판매 -4.5%·평론 -0.3, 선택 사양만이면 -1.5%·-0.1, 드문 장비를 기본으로 넣으면 +2%·+0.15(최대 3개), 평론 가감 합은 -1.5~+0.5, 배수 하한 0.6. 예(기대됨): 에어컨 대형 1985·중형 1990·소형 1995, 자동 변속기 1990·1996·2003, ABS 1995·1996·1997, 내비게이션 2010·2015·2020. 연도는 게임 균형 기준이다.
- **추천 구성**: 의무·기대 장비는 항상 기본 장비, 그 고객층이 중시하고(옵션 값 > 원가) 아직 기대되지 않는 장비는 선택 사양, 나머지는 안 넣음. 새 기획 기본값, [추천 구성으로], 풀체인지·페이스리프트의 '전작 이후 기대가 바뀐 장비'([한 번에 반영]), 개발 설계 단계의 [장비 다시 고르기]가 같은 규칙을 쓴다.
- 시대에 뒤처진 옵션은 효과가 줄고(기준 상승 때문), 어떤 옵션은 **규제 사건** 뒤 필수가 된다(없으면 판매 금지).

## 6. 개발 프로젝트
### 6.1 단계
1. **기획**(즉시): 차종 이름, 차체, 주 고객층, 동력, 옵션, 개발 방향, 예산 등급, 설계 기간.
2. **설계**(20 / 28 / 36주 선택, 2026-11-21 0.4.2: 8/12/16주에서 늘림. 주당 비용을 줄여 총 개발비 수준은 유지): 직원이 매주 능력치 점수를 만든다. 결함도 쌓인다.
3. **시험**(최소 2주, 끝은 플레이어가 정함): 결함을 줄인다. "출시" 버튼을 누르면 7장으로.

**개발비의 시대·차급 배수(1.0.0)**: 시제차 비용(주당)에 시대 배수를 곱한다. 시대 배수는 1980년 이전 1, 1990년 18, 2000년 58, 2010년 이후 70이고 사이는 보간한다(config dev.devEra). 차급별로는 `1 + (시대 배수 − 1) × (그 차체 기준가 ÷ 소형 세단 기준가)^0.5`로 적용한다(refBody·bodyExp). 1970년대는 이전과 같다. 세대 개발비 중앙값은 1990년대 약 660억, 2000년대 이후 약 1,200억대다(봇 측정). 이유: 공장 유지비를 낮추고 중후반 돈이 남는 것을 개발비로 조인다.

### 6.2 주간 점수
- 직원 1명의 주간 산출 = `주력 능력 / 8 × 예산 배수 × 컨디션 × 난수(0.85~1.15)`.
- 직무별 분배: 디자이너 → D 60% · U 40% / 엔지니어 → P 50% · E 50% / 테스터 → Q 100%.
- **팀 규모 체감**: 한 프로젝트에 n명이 붙으면 산출 합에 (n/4)^(−0.53)을 곱한다(4명 이하는 그대로). 20명이면 4명일 때의 약 2.1배. (2026-11-20 봇 측정으로 조정)
- **개발 방향**: 10점을 5개 능력치에 0~4점씩 배분. 능력치 배수 = `0.5 + 배분점/4`(2점이면 1.0).
- 예산 등급: 절약 ×0.8(비용 ×0.5) / 보통 ×1.0 / 과감 ×1.25(비용 ×2). 주간 개발비 = 참여 직원 월급 합 ÷ 4 × 비용 배수 + 시제차 비용.
- 최종 능력치 = `차체 배수 × (동력·옵션 점수 + 개발 점수)`.
- **보정 목표**(코더가 계수를 맞출 기준): 1970년에 초기 직원 4명·보통 예산·28주·균등 배분이면 표시 등급이 4.0~5.0이 되게 한다.

### 6.3 결함
- 설계 중 매주 결함 += `그 주 만든 점수 / 12`.
- 시험 중 매주 결함 −= `Σ 테스터 꼼꼼함/23 + Σ 엔지니어 기술/70`. (2026-11-21 0.4.2: 시간 척도 변경에 맞춰 /10, /30에서 조정)
- 화면에는 "남은 결함: 약 N개"(±15% 오차 표시).
- 출시 시 남은 결함 1개당 Q −1%(최대 −40%), **리콜 확률** = 연 `min(40%, 결함 × 2%)`. 리콜: 판매 누계 × 대당 15만원 비용, 평판 −5, 그 차 인지도 −20%.
- 시험 단계에서 결함이 0이 되면(시험 2주 이상) 프로젝트는 **출시 대기**가 된다. 출시 대기 중에는 주간 개발비가 들지 않고 직원은 풀려난다. (2026-11-20 추가)

### 6.4 동시 진행
개발팀은 본사 등급에 따라 1 → 2 → 3개. 직원은 한 번에 한 프로젝트에만 배치된다.

## 7. 출시와 판매
### 7.1 출시 설정
가격(슬라이더, 기준가의 0.6~2.0배), 월 마케팅비(0 / 소 / 중 / 대), 판매 지역(해금된 곳), 색상(외관만).

### 7.2 평론가 4명 (출시 직후, 각 1~10점)
- 성능파(P .6, D .4) / 살림꾼(U .4, E .4, Q .2) / 디자인파(D .7, Q .3) / 가성비파(전체 평균 × 가격 매력).
- 점수 = 표시 등급 가중합 ± 난수 0.7, 결함이 많으면 전원 −1.
- 평균 8 이상: "명차" 등록(기록 화면, 평판 +4). 평균 4 이하: 평판 −3.
- 풀체인지 차는 **전 세대 평균**과 비교한 문구가 붙는다(8.3).

### 7.3 월 판매량
**장비 기대(1.1.0)**: 판매 요인 분해에 '장비 기대' 항목이 있다(5.4의 매력 배수). 옛 저장의 출시된 차는 '옛 구성'으로 이 가감을 받지 않는다.

**자동 가격 정책과 최고 이익 가격(0.8.0)**: 차마다 정책을 고른다: 수동 / 기준가의 95·100·105% 유지 / 최고 이익 매달(허용 비율 80~120%, config pricePolicy). 매달 결산 때 정책대로 가격을 맞춘다. 가격을 손으로 바꾸면 정책이 풀린다. 정책이 켜진 차에는 재무 임원이 가격 제안을 하지 않는다. [최고 이익 가격으로] 단추는 이번 달 이익이 가장 큰 가격으로 바꾼다. 참고: 최고 이익 매달은 기준가 판매 봇보다 40년 자산이 크게 늘어난다(알려진 문제).

시장 칸 = 지역 × 차체(12칸). SUV 수요는 소형·중형·대형 세 칸이 나눈다(합은 이전의 SUV 한 칸과 같다, 0.6.0). 비중(1990~2030, 10년 단위): 소형 0 / 0.015 / 0.05 / 0.11 / 0.14, 중형 0.035 / 0.08 / 0.11 / 0.115 / 0.13, 대형 0.005 / 0.025 / 0.04 / 0.045 / 0.05. 칸마다 연 규모와 고객층 구성비가 있다(`market.json`, 10년 단위 표를 선형 보간).

```
매력(차, 고객층)   = Σ 가중치 × 표시 등급/5 × 궁합 × 유행(차체·동력, 연도) × 지역 취향
가격 매력          = (기준가 × 매력 / 판매가) ^ ε        … 0.2~2.5로 자름
점유 점수 A        = 매력 × 가격 매력 × 인지도 × 수명(차 나이)
점유율             = A² / (A² + Σ 경쟁 차의 A²)     … 지수는 config(2026-11-20 조정: 3이면 승자 독식이 심했다)
월 판매            = 칸 월 규모 × 고객층 비중 × 점유율   (모든 고객층에 대해 합산)
실제 판매          = min(월 판매, 그 차에 배정된 공장 생산량)
```
- 가격 매력의 벌점은 (기준가/판매가)^6이고, 기준가의 108%를 넘는 분에는 ^20을 한 번 더 곱한다(가격만 올려 돈을 버는 것을 막는 장치). (2026-11-20 봇 측정으로 조정, 2026-11-21 0.5.0 완만화: 108% 가격 첫 차 월 판매 0~7대 → 3~55대)
- **인지도**(0~1): 시작 = `0.15 + 평판/250 + 평론 보너스 + 차종 자산(8.3)`. 매달 마케팅비와 입소문(품질 등급)으로 목표값에 수렴.
- **수명**: 출시 0~3개월 0.6 → 1.0으로 상승, 출시 30개월까지 1.0 유지, 그 뒤 매달 −0.6%. (2026-11-21 0.4.2: 시간 척도 변경에 맞춰 조정) 여기에 5.1의 "기준 상승"이 겹쳐 4~6년이면 눈에 띄게 줄어든다.
- 주 고객층으로 고른 층은 인지도 +25%.
- **기준가**에는 그 시점의 의무 장비(11.3) 원가가 포함된다. 포함하지 않으면 1990년대 후반에 기준가대로 팔아도 마진이 0이 된다. (2026-11-21 0.4.2)
- **시장 기준가 하락**: 1995년부터 기준가가 연 0.4% 내려가며 최대 3.5%까지 내려간다. (2026-11-21 0.5.1, 0.7.0에서 상한 6% → 3.5%: 6%이면 대당 이익의 2/3가 깎여 2010년대에 공장 5등급 유지비를 감당하지 못했다. 보통 신중 봇 60년 생존 6/20 → 18/20)
- 대당 이익 = 판매가 − 원가(차체 × 동력·옵션 가산 × 공장 원가 배수 × 시대 원가 상승) − 지역 물류비.
- **차별 기준가와 옵션 값(1.0.0)**: 차의 기준가 = 차급 기준가 + 의무 장비(11.3) 원가 + 옵션 값. 옵션 값 = 옵션 원가 × (1 + 시대 원가 상승) × 1.05(그 옵션이 올리는 능력치에 대한 이 고객층의 가중치 평균이 0.2 이상일 때) 또는 × 0.8(아닐 때). 가격 매력·평론가 가성비파·최고 이익 가격·자동 가격이 모두 이 같은 값을 쓴다. 이전에는 기준가가 옵션을 반영하지 않아 옵션을 넣을수록 기준가에 팔아도 적자였다(사용자 보고). 맞는 옵션의 이득은 +15~19%다(봇 측정).
- **동력 시장 가산(1.0.0)**: 하이브리드·전기차는 원가가 비싼 만큼 시장 가격도 높다. 하이브리드 +16%, 전기 2010년 +30% → 2020년 18% → 2030년 9% → 2040년 5%(powertrains.json premium, 연도 표 보간). 이전에는 기준가에 팔면 적자였다.
- **시대별 원가 상승(1.0.0)**: 1975년 0에서 1995년 +7%까지 직선으로 원가 배수에 곱한다(옵션 값을 기준가에 넣은 뒤 1990년대 이익률이 올라 되돌림).
- **노후 차(1.0.0)**: 수명 나이 72개월부터 매달 3%씩 추가로 줄어든다. 이 노후 몫의 하한은 30%다(하한이 없으면 13년 된 차의 수명이 4%가 되어 판매가 0이 된다). 11년 된 차가 수명 24%에도 월 수십억을 벌어 풀체인지할 이유가 약했다(사용자 화면).
- **판매 요인 분해(0.10.0)**: 가격·인지도·광고·수명·등급·궁합·경쟁사·같은 차급의 우리 차·시대 사건·생산 한도가 판매에 준 영향을 %로 보여 준다. 실제 수요 계산과 같은 함수를 요인 하나씩 기준 상태로 바꿔 가며 다시 불러 구한다. 기준 상태: 인지도 0.5 등(config factors). 지난달 판매가 생산 라인 하나 몫의 30% 미만이거나 전월보다 30% 넘게 줄면(config factors.slumpShare·dropShare) 맨 위에 요약 한 줄을 띄우고, 1% 미만 요인은 숨긴다(config factors.minShow). 인지도·광고 요인은 서로 겹친다.

### 7.4 경쟁사 (규칙 기반, 완전한 회사 시뮬레이션 아님)
- 6곳: 도요다(전 차급·품질), 현다이(가성비), 포티(픽업·대형), 폴크스바게(해치백·유럽), 비엠브이(고급·성능), 테슬러(2012년 등장·전기). 이름은 확정 아님.
- 각 사는 강한 칸·약한 칸이 있고, 칸마다 A값이 `1.0 ± 강약 ± 난수`인 차를 4~7년 주기로 갈아 낸다. 가끔 "히트작"(A +0.3, 2년) 사건.
- 경쟁 차의 기본 A는 1970년 0.42에서 해마다 0.05씩 올라 최대 1.25(1986년쯤)까지 강해진다. (2026-11-20 봇 측정으로 조정)
- 강한 칸·약한 칸 목록에 소형·중형·대형 SUV 칸이 따로 있다(0.6.0).
- **경쟁사의 대응(1.0.0)**: 지난달 한 차급(차체)에서 우리 판매가 그 칸 월 규모의 10%(rivals.response.share0)를 넘으면, 넘은 몫 × 3(k)만큼 그 칸의 경쟁 차 A가 세진다. `경쟁 차 A × (1 + 켬 × 3 × max(0, 우리 판매 / 칸 규모 − 0.10))`. 켬은 1985년 0에서 1995년 1까지 서서히 올라간다. 한 차급을 장악한 회사일수록 웃돈·판매가 줄어드는 '쉬운 독점 방지' 규칙이다. '잘할수록 경쟁이 세진다'는 체감 확인이 필요하다.
- **경쟁 1부: 모델 이름과 얼굴(2.0.0, 수치는 config.rivals.view, 계산은 `car/src/sim/rivals.ts`)**: 판매 계산(위의 경쟁 차 A)과 게임 난수는 그대로 두고, 그 위에 보이는 값만 더했다. 같은 시드의 판 결과(판매·현금)는 1.6.1과 같다.
  - 모델 이름: 회사마다 이름 목록(`rivals.json`의 models, 차체 수 이상)을 시드 해시로 섞어 차체 순으로 나눈다. 세대가 바뀌어도 이름은 그대로이고 세대 번호가 붙는다("세실리오 3세대"). 이름은 지어낸 것(현다이: 우리말, 포티: 미국 지명풍, 도요다: 라틴어풍)이며 실제 모델명은 쓰지 않는다.
  - 겉으로 보이는 값(저장하지 않는 파생값): d = 모델 기본 A − 그때 경쟁 차 기본 A(강약 + 강약 난수). 추정 평론 = 6 + d × 10(1~10). 히트작 = 강약 난수 몫이 noise의 60% 이상(대략 다섯에 하나)이거나 경쟁사 히트작 사건(11.2)이 걸린 칸. 능력치 5개 = (출시 때 추정 평론 − 낡은 만큼) + 회사 모양(`shape`) ± 0.6(해시). 가격 = 시장 기준가 × (1 + (추정 평론 − 6) × 2%). 칸 점유(대략) = (1 − 내 몫) × A² / Σ 경쟁 차 A²(고객층·사건은 무시).
  - 지난 세대: 지금 모델에서 주기(시드 해시)를 거꾸로 빼서 세대별 출시 달을, 갱신 규칙의 해시로 기본 A를 다시 셈한다. 첫 모델(1세대)의 강약 난수는 게임 난수라 알 수 없어 강약만으로 어림한다.
  - 화면: 차고 상세 [같은 차급의 경쟁 차와 비교](차고 표에서 한 대만 골라 [경쟁 차와 비교]도 같다) — 내 차 옆에 같은 차급 경쟁 모델 3종(이름·세대·출시 연도·추정 평론·가격·점유·능력치 막대)과 앞서는·뒤지는 능력치. 내 차 2~4대 비교의 경쟁사 줄은 그 차급에서 가장 많이 팔리는 경쟁 모델. 재무 화면의 경쟁사 줄을 누르면 회사 라인업(모델·차체·세대·출시 연도·추정 평론·히트작)과 한 줄 성격, 모델을 누르면 지난 세대. 썸네일은 기존 차 생성기로 그린다(회사별 색 경향).
  - 뉴스: 경쟁 모델이 세대교체하면 뉴스 탭에 한 줄("도요다, 세실리오 3세대 출시. 「아리아」와 같은 소형 세단, 추정 평론 6.1."). 내가 그 차급에 차를 팔 때만 관련을 덧붙이고 알림을 띄운다(알림 유형 '경쟁사 신차'로 끌 수 있다). 늦은 시작의 과거 세대교체는 뉴스로 만들지 않는다. 뉴스 보관 개수 60 → 120.
  - 경쟁 2부(3.5.0)로 미룬 것: 경쟁사의 대응 신차·가격 전쟁·인재 빼가기·기술 제휴·올해의 차 시상식.

### 7.5 지역
| 지역 | 해금 | 특징 |
|---|---|---|
| 국내 | 시작 | 1970년 연 2만 대 → 1990년 100만 → 2000년 105만 → 2010년 110만 → 2020년 이후 115만(시장 포화, 2026-11-21 0.5.0) |
| 아시아 | 평판 25 + 5억 | 저가·소형 선호, 꾸준히 성장 |
| 유럽 | 평판 45 + 30억 | 해치백·디젤 선호, 품질 기준 높음 |
| 북미 | 평판 60 + 80억 | 가장 큼, 대형·픽업·SUV 선호 |

지역별 시장 칸은 차체 12종마다 하나씩이다(SUV는 소형·중형·대형 세 칸, 7.3). (2026-11-21 0.6.0)

## 8. 차종의 일생: 연식 유지 → 페이스리프트 → 풀체인지
차는 **차종(이름) → 세대 → 판(초기형 / 페이스리프트)** 3층으로 관리한다. 예: 「미라지」 2세대 페이스리프트.

### 8.1 한눈에
| | 페이스리프트(부분변경) | 풀체인지(세대교체) |
|---|---|---|
| 뜻 | 뼈대는 그대로, 얼굴과 옵션만 손봄 | 뼈대부터 새로 만든 다음 세대 |
| 가능 시점 | 그 세대 출시 **18개월 뒤**부터, 세대당 **1회** | 그 세대 출시 **36개월 뒤**부터 |
| 기간 | 설계 12주 + 시험 2주~ (약 14~15주) | 일반 개발과 같음(20~36주 + 시험, 신차 개발 약 42~54주) |
| 비용 | 그 세대 개발비의 **40%** (2026-11-20 봇 측정으로 조정) | 일반 개발비의 **85%**(같은 차체일 때), 차체를 바꾸면 100% (2026-11-20 봇 측정으로 조정) |
| 바꿀 수 있는 것 | 옵션, 앞뒤 디자인, 색, 가격. 동력은 **같은 종류의 최신 단계**로만 | 전부(차체 크기 변형, 동력 종류, 고객층) |
| 못 바꾸는 것 | 차체 종류·크기, 동력 종류 | 차종 이름(이어받음) |
| 능력치 | D +10%, 디자인 외 능력치 ×1.025, 옵션·동력 갱신분 반영, 남은 결함 절반 제거 | 새로 계산 (2026-11-20 봇 측정으로 조정) |
| 판매 효과 | 수명 나이를 **60%로 되돌림**, 인지도 +0.06 | 새 수명 시작 + **차종 자산** 인지도 보너스 (2026-11-20 봇 측정으로 조정) |
| 생산 | 멈추지 않음(전환 달 생산 −30%) | 새 세대 출시 달에 전 세대 단종(재고 처분 1개월) |
| 화면 | 앞·뒤 모습만 바뀜 | 차 전체 모양이 바뀜 |

### 8.2 페이스리프트 규칙
- 설계 12주 동안 디자이너 점수만 D에 추가된다(상한: 그 세대 원래 D의 +10%). 디자인 외 능력치(P·E·U·Q)는 ×1.025로 오른다. (2026-11-21 0.4.2: 설계 4주 → 12주, 디자인 외 능력치 +2.5% 추가. 출시 36개월 리프트 시 5~11개월 회수, 세대 순이익 +20~25%, 봇 측정)
- 결함: 남은 결함 × 0.5로 시작, 새 결함은 일반의 1/3 속도로 쌓인다.
- 평론가는 다시 평가하지 않는다. 대신 신문에 한 줄 기사와 "페이스리프트 효과" 판매 그래프 표시.
- 손익 카드의 페이스리프트 비교는 '하지 않았을 때 추정'(리프트 없이 그대로 판 경우의 판매·이익)과 비교한다(1.0.0 반사실 비교).
- 미리보기에 예상 월 판매·월 이익의 전후와 회수 개월을 보여 준다. 출시 30개월 전이면 "지금은 효과가 작습니다"를 띄우고, 기본 팀은 디자이너 중심 추천 팀이다. (2026-11-21 0.5.1)
- **수명 되돌림(1.0.0)**: 수명 나이를 0.6 → 0.3으로 되돌린다(30%만 남김). 출시 36개월 리프트가 수요가 정점의 25%가 되는 때를 24~41개월 늦춘다(고정 경쟁 차 측정, 회수 4~8개월). 이전 값 0.6은 12~29개월이었다.
- 너무 늦으면 효과가 작다: 세대 나이 60개월 이후에는 수명 되돌림이 30% → 80%로 약해진다. (2026-11-20 봇 측정으로 조정)

### 8.3 풀체인지 규칙
- **차종 자산**(0~0.3): 이름이 쌓은 신뢰. `자산 = clamp(0.03 × 전 세대 평론 평균 − 0.09, 0, 0.2) + min(0.1, 누적 판매/15만)`(2026-11-21 0.5.1: 공식 변경). 새 세대의 시작 인지도에 더해진다. 리콜이 있었다면 −0.05.
- **전작 비교**(2026-11-21 0.4.2 변경): 새 세대의 원점수(차체 배수를 나눈 절대 성능) 평균을 전 세대 마지막 판과 비교한다. 5% 넘게 낮으면 평론가 전원 −1, 기사 제목 '전작만 못하다'. 10% 이상 높으면 +0.5, '진화했다'. 그 사이면 '전작과 비슷하다'. 시대 기준이 올라 표시 등급이 낮아지는 것은 감점하지 않는다. 이유: 출시 당시 표시 등급으로 비교하면 꾸준히 연구해도 풀체인지의 절반 넘게 감점이었다.
- **기존 고객 재구매**: 전 세대 누적 판매의 3%가 새 세대 첫 12개월에 걸쳐 추가 수요로 들어온다(품질 등급 3 미만이면 0. 2026-11-21 0.5.1: 5 → 3). 전작만 못할 때는 해결책 목록을 보여 준다..
- 0.8.0: 풀체인지 기획은 전작의 고객층·동력·옵션·개발 방향·예산·설계 기간을 물려받은 요약에서 시작한다. 전작 이후 새로 가능해진 항목을 표시하고 [새 기술 반영]으로 넣는다.
- **풀체인지 비용(1.0.0)**: 같은 차체면 그 세대 개발비의 70%(전에는 85%), 새 차체면 100%.
- 차체 종류를 바꾸는 풀체인지(세단 → SUV)는 가능하지만 차종 자산의 절반만 이어진다.
- 세대 번호는 자동으로 올라가고, 기록 화면의 **차종 계보**에 세대별 사진(3D 캡처)·판매·평점이 남는다.
- 단종만 하고 후속을 내지 않을 수도 있다. 3년 넘게 비워 둔 이름을 다시 쓰면 "부활" 기사와 자산의 절반.

### 8.6 단종
- 판매 중인 세대는 **언제든** 단종할 수 있다(확인 창 1회). 개발 중인 프로젝트는 "개발 취소"(쓴 돈은 돌아오지 않음)로 따로 처리한다.
- 단종하면: 그 달 말까지만 판매하고(마지막 달 판매 ×0.5, 재고 처분), 다음 달부터 생산 라인 1개가 빈다.
- 차종 이름과 차종 자산은 남는다. 단종 후 **36개월 안에** 같은 이름으로 풀체인지를 내면 자산을 그대로 잇고, 그 뒤에는 "부활"로 자산의 절반만 잇는다(8.3).
- 잘 팔리는 차(최근 3개월 평균이 정점의 70% 이상)를 단종하면 평판 −2, 신문에 "아쉬운 퇴장" 기사. 안 팔리는 차의 단종은 불이익이 없다.
- 판매가 월 10대 미만으로 6개월 이어지면 "단종을 권합니다" 조언이 뜬다. 자동 단종은 하지 않는다.
- 단종된 세대는 기록 화면의 차종 계보에 "단종(연·월)"으로 남는다.

### 8.7 신차 기획의 첫 화면: 어디서 시작할지 고르기 (사용자 2026-11-20)
[신차 기획]을 누르면 먼저 아래 중 하나를 고른다(Game Dev Story의 "신작 / 속편" 선택과 같은 자리).
| 선택 | 뜻 | 조건 |
|---|---|---|
| **새 차종 만들기** | 새 이름으로 1세대를 만든다 | 항상 가능 |
| **기존 차종의 다음 세대(풀체인지)** | 내 차종 목록에서 골라 다음 세대를 만든다. 이름·차종 자산을 이어받는다(8.3) | 그 차종의 현 세대가 출시 36개월 이상이거나 단종 상태 |
| **기존 차종 손보기(페이스리프트)** | 판매 중인 세대의 얼굴·옵션을 손본다(8.2) | 출시 18개월 이상, 세대당 1회 |
- 기존 차종을 고르는 목록에는 차종마다 세대, 최근 평론, 누적 판매, 차종 자산(이름값), 지금 가능한지와 불가능한 이유를 보여 준다.
- 조건이 안 되는 선택지는 흐리게 하고 이유를 쓴다("출시 후 36개월이 지나야 합니다. 앞으로 14개월").
- 차고의 차종 카드에 있는 [페이스리프트] [풀체인지] 버튼은 이 화면의 해당 선택으로 바로 들어가는 지름길이다.

### 8.8 실패한 차의 수습 (0.10.0)
- 대상: 평론 평균 4.5 이하이거나 최근 3개월 판매가 생산 라인 하나 몫의 30% 미만인 차(긴급 개선). 가격 인하 판매는 수명 막대 50% 이하이거나 평론 4.5 이하일 때.
- 긴급 개선: 테스터·엔지니어가 8주 동안 시험만 한다(결함 감소는 시험과 같은 식). 주간 비용 = max(세대 개발비 × 12% ÷ 8, 그 팀의 보통 시험 한 주 비용). 뒤쪽 하한은 처음부터 시험을 더 한 경우보다 싸지 않게 하려는 것이라, 개발비가 작은 차는 실제로 개발비의 약 20%가 든다. 끝나면 품질 ×1.04, 평론·인지도·수명은 그대로. 세대당 1회.
- 가격 인하 판매: 시장 기준가의 88%로 6개월 고정. 시작할 때 인지도 +0.08. 끝나면 평판 감점 없이 자동 단종한다.
- 수치는 config rescue.

### 8.4 플레이어에게 주는 판단
- 화면의 차종 카드에 **수명 막대**와 조언 한 줄: "판매가 정점의 60%로 떨어졌습니다. 페이스리프트를 고려하세요."
- 의도한 흐름(후보): 출시 → 3년 차 페이스리프트 → 6~7년 차 풀체인지. 실제 업계 관행과 비슷하게 잡았다(작성자 기억 기준, 미대조).
- 경쟁사도 같은 규칙으로 페이스리프트·풀체인지를 한다(7.4의 주기 안에서 A값 변화로 표현).

### 8.5 3D 표현
- 차 모양 = **차대 값**(길이·높이·지붕선 등) + **얼굴 값**(전조등·그릴·범퍼·후미등 모양) + **시대 스타일**.
- 페이스리프트: 얼굴 값만 새로 뽑는다. 풀체인지: 차대 값과 시대 스타일까지 새로 뽑는다.
- 값은 `차종 ID + 세대 + 판`을 시드로 한 난수에서 나오며, 플레이어가 후보 3개 중 고른다. 결과는 저장 파일에 값으로 저장한다(재현 보장).

## 9. 회사
### 9.1 직원
- 직무: 디자이너(디자인), 엔지니어(기술), 테스터(꼼꼼함), 영업(영업력). 능력 0~100, 월급 = `250 + 능력 × 12`만원.
- 채용: 공고 3등급(500만 / 2,000만 / 1억) → 후보 3명 중 선택. 등급이 높을수록 능력 범위가 높다. 후보의 성장 한계(잠재력) = 능력 + 5~20, 3등급 공고는 평판 40 이상. (2026-11-20 봇 측정으로 조정)
- 성장: 프로젝트를 마치면 경험치, 교육(비용 = 능력 × 40만원(최소 500만) → 능력 +1~3, 직원당 연 1회, 4주 동안 일 못 함). 능력 상한은 개인별 잠재력. (2026-11-20 봇 측정으로 조정)
- 컨디션: 프로젝트 주마다 조금씩 떨어지고(과감 예산이면 더 빨리) 쉬는 주에 회복. 0.3 미만이면 산출 ×0.6, 0.6 미만이면 ×0.85. (2026-11-20 봇 측정으로 조정)
- 영업 직원: 인지도 수렴 속도와 법인 판매에 보너스.
- 일괄 교육·일괄 휴식: 직원 표에서 여러 명을 골라 한 번에 보낸다. 교육 가능한 직원을 모두 고르는 단추가 있고, 확인 창에 총 비용·보낼 수 없는 사람과 이유·개발 지연 경고를 보여 준다. (2026-11-21 0.6.0)
- 성장 기록(0.10.0): 입사 시기, 연도별 능력, 참여한 차, 임원 경력을 직원 상세 '경력'에 보여 준다. 인사 임원의 제안에도 이 기록을 쓴다.
- 정원: 본사 등급 1~7 = 6 / 8 / 12 / 16 / 20 / 30 / 40명(6·7등급은 2026-11-23 3.0.0). 임원과 자회사 사장은 정원 밖이다(9.7·9.9, 0.8.0).

### 9.2 본사 등급
정원은 등급별 6/8/12/16/20/30/40(2026-11-21 0.5.0: 1등급 4 → 6, 2026-11-23 3.0.0: 6·7등급 추가. 사용자 지시: 차 6대에 직원 20명 상한은 모자라다). 임원은 정원에 넣지 않는다(0.8.0).

| 등급 | 이름 | 조건 | 정원 | 개발팀 | 옵션 슬롯(1.1.0 폐지) | 월 유지비 |
|---|---|---|---|---|---|---|
| 1 | 창고 공장 | 시작 | 6 | 1 | 2 | 500만 |
| 2 | 소형 사옥 | 5억 | 8 | 1 | 2 | 1,500만 |
| 3 | 본사 빌딩 | 40억 + 평판 20 | 12 | 2 | 3 | 5,000만 |
| 4 | 연구 단지 | 300억 + 평판 55 | 16 | 2 | 4 | 1.5억 |
| 5 | 글로벌 본사 | 1,500억 + 평판 80 | 20 | 3 | 4 | 4억 |
| 6 | 그룹 본사 | 8,000억 + 평판 120 | 30 | 4 | 4 | 10억 |

### 9.5 평판 (0 이상, 위쪽 상한 없음)
평론, 시상, 명차 등록, 리콜, 파산 위기로 오르내린다. 오르는 길은 출시 평론(`(평론 평균 − 5) × 1`)과 연말 연간 판매(`min(2, 연 판매 / 3000)`)다. (2026-11-21 0.4.2)

**평판 상한 없음(1.0.0, 사용자 지시)**: 100에서 자르지 않는다. 효과는 100까지 평판 그대로이고, 넘으면 완만해진다: `효과 = 100 × (1 + ⅓ × log2(평판 / 100))`(200이면 133, 400이면 167). 인지도·채용 후보 능력 가산에 쓴다. `Q.reputationInfo`가 지금 평판의 효과 목록과 다음 문턱을 돌려주고, 화면의 평판 ⓘ에 보인다.

**0.5.1 규칙(2026-11-21)**: 평론 5 미만이어도 출시 감점은 없고 5를 넘는 만큼만 가산한다. 혹평 기준은 평론 3.5 이하. 리콜 감점은 −(누적 판매/5,000)(0.5~3)에 난이도 배수를 곱한다. 누적 판매 1천·5천·1만·5만·10만·50만·100만 대 달성 때 +2~3. 연간 판매 몫 상한은 3. 판매 중인 차의 평론 평균이 6 이상이면 연말 +1. 평판이 변한 이유는 알림으로 보여 준다. 인지도 시작값, 지역 해금, 본사 승급, 채용 후보 수준에 쓰인다. 매년 50 쪽으로 2%씩 끌려가지 않는다(쌓은 평판은 유지, 대신 사건으로 깎임).

### 9.9 자회사와 고급 브랜드 (2026-11-23 3.0.0, 수치는 car/src/config.ts의 subs, 계산은 `car/src/sim/subs.ts`)
- **구조**: 자회사를 본사처럼 통째로 시뮬레이션하지 않는다. 브랜드 자회사는 경쟁 모델(7.4)과 같은 구조(차급별 모델: 세대·주기·기본 A, 이름, 추정 평론 등 파생 표시값)의 "내 편 경쟁사"다. 시장에서는 경쟁 차와 같은 방식(A^2 몫)으로 그 차급 수요를 나눠 갖고, 그 판매에서 자회사 이익이 나온다. 사업 자회사(부품·금융)는 모델 없이 본사 원가·판매에 효과를 주고, 그 규모로 이익을 낸다. 게임 난수를 쓰지 않는다(시드 해시). 자회사가 없는 판의 결과는 2.0.0과 같다.
- **종류와 설립**(종류마다 한 곳): 고급 브랜드(중형·대형 세단, 쿠페, 중형·대형 SUV, 스포츠카 / 부유층·마니아·청년, 시장 기준가 ×1.3, 대당 원가 ×1.2, 물량 ×0.7, 설립비 2,000억, 평판 120), 보급형 브랜드(경차·해치백·소형 세단·소형 SUV·미니밴·중형 세단 / 직장인·가족·청년·법인, 가격 ×1, 원가 ×0.97, 물량 ×1.15, 1,500억, 평판 100), 부품 회사·할부 금융(각 1,000억, 평판 100). 본사 4등급부터, 자회사 수 상한은 본사 4등급 1곳·5등급 3곳·6·7등급 4곳. 설립비는 현금에서 바로 나가고 장부에 '자회사 투자'로 적는다. 별도 이름(기본: 엘리온·모아·○○ 부품·○○ 캐피탈)·로고 색·브랜드 평판(설립 때 본사 평판 × 0.6(고급)·0.4(보급형)).
- **돈**: 자본 = 설립비 + 추가 투자 + 재투자. 월 생산 한도 = 자본 ÷ 4,000만원, 모델 수 상한 = 자본 ÷ 1,000억(맡은 차급 수 이내, 최소 1). 월 비용 = 판매 원가 + 모델마다 개발비(시장 기준가 × 20 × 전략·공유 배수) + 유지비(쓰는 설비 = min(자본, 판매 대수 × 4,000만원)의 0.2%, 사업 자회사는 자본의 0.2%) + 사장 월급. 남는 자본에는 유지비가 없다. 이익 × 배당 비율(플레이어가 0~100%, 기본 50%, 전략이 배수를 곱한다) → 본사 현금(장부 '자회사 배당', 본사 이익에 더한다), 나머지는 자본으로 재투자. 손실은 자회사 자본이 떠안는다. 매각하면 자본 × 0.7을 받는다.
- **모델의 세기**: 새 세대의 기본 A = 그때 경쟁 차 기본 A + 종류(고급 +0.03) + 전략 + 공유 범위 + 사장 0.1 × (능력/100 − 0.5)(사장이 없으면 능력 25로 본다) + 0.16 × (본사 기술 수준 − 1)(그해까지 나온 기술 중 연구한 몫) + 본사 투자 0.04 × log2(본사가 넣은 돈 ÷ 설립비)(최대 0.2) + 0.05 × (브랜드 평판 − 100)/100 ± 0.06(해시). 이번 달 점유 점수 = 기본 A의 노화(경쟁 차와 같은 수명·페이스리프트) × 고객층 궁합 × (가격 배수)^−2 × 브랜드 인지도(min(1, 0.45 + 평판/250)). 추정 평론은 경쟁 모델과 같은 셈(6 + (기본 A − 그때 경쟁 차 기본 A) × 10).
- **판매**: 칸 규모(시대 사건·유행·동력, 전기차는 충전 인프라) × (1 − 본사 몫) × a² ÷ (경쟁 차 A² + 자회사 모델 a²) × 물량 배수, 생산 한도까지. 경쟁 모델의 점유(7.4 표시값)도 자회사 모델을 넣어 나눈다.
- **제 살 깎기**: 같은 차급에 자회사 모델이 있으면 본사 차의 경쟁 합에 그 a² × 0.25를 더한다(작게). 자회사 상세에 본사 차마다 줄어든 수요(대·%)를 보인다(측정: 대개 0.1~5%).
- **사업 자회사**: 규모 = min(3, √(자본 ÷ 설립비)) × (0.75 + 사장 능력/200). 부품: 본사 대당 원가 × (1 − 1% × 규모)(최대 3%), 이익 = 본사 원가 × 0.5% × 규모. 금융: 본사 판매 × (1 + 1.5% × 규모)(최대 4%), 이익 = 본사 매출 × 30% × 1.4% × 규모. 공유 범위·영역·모델은 없다.

- 개발 탭의 왼쪽 무대는 개발 중일 때 **비스듬히 내려다본(쿼터뷰) 미니어처 사무실**을 보여 준다. 개발 중인 차는 사무실 한쪽에 작게 둔다. 차고 탭은 지금처럼 3D 차가 주인공이다.
- 그림은 2D(SVG)로 그린다(3D 아님: 가볍고 빨리 만든다). 사용자 피드백(2026-11-20: 닭장 같고 사람이 너무 크고 만화 같다)에 따라 **실제 사무실처럼** 그린다: 사람은 현실 비율로 작게, 4인 책상 묶음 사이에 통로, 디자인 스튜디오·시험실·회의실·탕비 공간으로 구역을 나누고, 차분한 색. 직원은 통로를 따라 걸어 다니며 상태는 표정이 아니라 자세로 보인다. 기본 화면은 일하는 구역을 가까이 본 모습이고 버튼 없이 **핀치로 확대·축소**, 끌어서 이동, 화면을 옮긴 뒤 나타나는 "원위치" 버튼(태블릿 가로 화면 기준).
- 직원이 각자 책상에서 일한다. 설계 중 타자·스케치, 시험 중 테스터의 돋보기, 쉬는 중 느긋한 동작, 과감 예산이면 빠르게·땀, 컨디션이 낮으면 축 처짐.
- 머리 위로 그 주에 실제로 쌓은 점수가 튀어 오르고(규칙 엔진의 주간 기록을 그대로 표시), 말풍선이 가끔 뜬다(한 번에 최대 2개).
- **확장 대비**: 방 크기와 책상 배치는 본사 등급(1~7, 책상 4/8/12/16/20/32/40자리)에 따라 자동으로 정해진다. 직원 수가 바뀌어도 자리 계산이 되도록 처음부터 "등급 → 방 크기, 인원 → 책상 자리" 함수로 만든다. 등급이 오르면 방이 넓어지고 소품(화분, 회의 탁자, 연구 장비)이 늘어난다.
- 보여 주기만 한다. 규칙(점수·결함)은 바꾸지 않는다. 직원이 "불타오르는" 식의 추가 규칙은 3단계에서 따로 설계한다.

**1.0.0 사무실**: 사무실 등급별 모습, 시대별 집기, 임원실. 화면 분위기는 시대별 7단계로 바뀐다.

화면 스타일 기준: `docs/car/demo/car-studio.html`(밝은 스튜디오, 잉크색 버튼, 주황 강조, 굵은 고딕 + 좁은 숫자체).

- **저장 형식 5(1.1.0)**: 차 스펙·세대에 equip(장비별 std/opt)을 둔다. 4에서 올릴 때 기존 options는 모두 기본 장비로 변환하고, 이미 출시된 차는 '옛 구성'으로 표시해 장비 기대의 감점·가점을 면제한다(새 판을 내면 적용). 개발 중 차는 설계 단계까지 장비를 다시 고를 수 있다. options 필드는 equip의 기본 장비 목록으로 함께 남는다.

### 15.1 기기 연동 (2026-11-23 1.6.0, `car/src/io/cloud.ts`)
- 서버가 없는 정적 사이트라, 사용자의 GitHub 계정에 비밀 Gist 하나를 보관함으로 쓴다. 기기마다 토큰(gist 권한만)을 한 번 넣는다. 토큰은 그 기기의 localStorage에만 두고 저장·내보내기 파일·오류 문구에 넣지 않는다.
- 보관함: 내 Gist 목록에서 `carcompany-sync-meta.json` 파일이 있는 것을 찾고, 없으면 `public:false`로 만든다. 파일 두 개: meta(rev, 저장 시각, 기기 이름, 회사 이름, 게임 내 날짜, 저장 형식, 게임 버전)와 본문(자동 저장 한 판 + 지난 판의 차 이름 목록, JSON → gzip → base64). 본문이 1MB를 넘으면 Gist API가 내용을 잘라(`truncated`) 주므로 `raw_url`로 토큰 없이 받는다.
- 연동 대상은 자동 저장 한 판과 지난 판의 차 이름뿐이다(저장 칸 1~3은 연동하지 않음). 올리기는 자동 저장 뒤 60초에 한 번까지, 메뉴의 [지금 올리기]. 받기는 처음 화면에서 meta의 rev가 이 기기가 마지막으로 맞춘 rev와 다르면 묻는다. 불러오기 전 이 기기의 자동 저장은 '연동 전 백업' 칸에 한 벌 남긴다.
- 충돌: 올릴 때 서버 rev가 이 기기가 아는 rev와 다르면 올리지 않고 멈춰, 사용자가 [이 기기 것으로 덮어쓰기] / [서버 것 불러오기]를 고른다. 병합하지 않는다. 서버 저장 형식이 이 기기보다 새 것이면 불러오지 않고 새로 고침을 안내한다.
- 실패(오프라인·401·403·그 밖)는 플레이를 막지 않는다. 메뉴의 기기 연동 칸에 한 줄, 같은 실패는 알림 한 번. 저장은 기기 안에 남는다.
- CS2와 다른 점: CS2는 Paradox 계정 클라우드 저장을 쓴다(내 기억 기준). 이 게임은 서버가 없어 사용자의 GitHub Gist를 쓴다.

## 16. 검증 계획
- 규칙마다 헤드리스 테스트(예: 결함 0이면 리콜 없음 / 페이스리프트는 세대당 1회 / 풀체인지 후 전 세대는 다음 달 단종 / 차종 자산은 0~0.3).
- 결정론 테스트: 같은 시드·같은 명령 기록 → 같은 상태 해시. 저장 → 불러오기 → 이어서 실행 = 끊지 않은 실행.
- **균형 봇** 5종 × 시드 20개 × 60년: 방치 / 신중(평균 예산, 3년 리프트·6년 체인지) / 공격(과감 예산, 빠른 확장) / 리프트 안 함 / 무작위.
  기대: 방치는 10년 안에 파산, 신중은 70% 이상 생존, 공격은 생존율은 낮고 상위 성적은 높음, **"리프트 안 함"은 신중보다 뚜렷이 불리**(이 기능이 의미 있다는 증거).
- **1.0.0 균형 기준 봇**: 자동 가격 + 임원 봇(편의 기능을 쓰는 보통 플레이)을 기준으로 삼는다. 목표 범위(시드 20): 보통 현금 40년 약 5.5조·60년 약 10.5조, 쉬움 60년 약 17조(상한 20조에 가까움), 쉬움 서툰 봇 30년 생존 20/20. 보통에서 편의 기능을 쓰지 않는 서툰 봇의 60년 생존은 13/20 → 11/20(30년까지 20/20).
- 스냅샷 테스트: 시드 고정 10년 요약.
- Playwright 스모크: 페이지 로드, 콘솔 오류 0, 캔버스 렌더, 신차 1대 출시까지 클릭.
- 화면은 단계마다 사용자 눈 확인.

## 17. 위험과 미결
