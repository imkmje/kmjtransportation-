구현 담당에게 넘기는 작업 목록이다. 각 항목에 근거의 종류를 적었다.
- **[측정]** 자동 시뮬레이션을 돌려 숫자로 확인함(자유 모드, 운수권 켬, 자동 전략 '전부', 시드 1~4, 10년)
- **[화면]** 데스크톱 크롬 1180×820 스크린샷에서 직접 봄
- **[코드]** 코드를 읽어 확인함(실행으로 재현하지는 않음)

아이패드 실기기에서는 아무것도 확인하지 못했다.

## 2. 균형 (자유 모드가 지금 어떻게 돌아가는지)

| ID | 내용 | 근거 |
|---|---|---|

| BAL-2 | **주력 노선 점유율이 바닥(10%)에 붙는다.** 서울⇄도쿄 점유율이 8번 실행 모두 10~15%. 10%는 코드의 최저 한도라, 실제로는 그보다 더 밀리고 있다는 뜻. 경쟁사를 약하게 한 비교 실행에서도 10~31%. 원인: 경쟁사마다 "수요가 가장 큰 노선"을 고르다 보니 같은 노선에 5곳 넘게 몰린다 | [측정] |
| BAL-3 | **입찰은 경쟁사가 다 가져간다.** 운영권 3~4건이 모두 경쟁사 낙찰. 대형 항공사가 도쿄·상하이·베이징을 연달아 가져간 실행도 있다. 사람이 이길 값인지 판단할 근거가 화면에 없다(얼마까지 오를지 모름) | [측정] |
| BAL-4 | **경쟁사가 선점한 슬롯이 크다.** 도쿄 8, 베이징 8, 델리 9, 부산 8개까지. 내 확장을 강하게 막는다 | [측정] |
| BAL-5 | **시상식 수상자가 해마다 같다.** 경쟁사 정시율·서비스 점수가 고정값(운영 효율·유형)이라 같은 회사가 3년 연속 받는다. 해마다 조금씩 흔들리게 해야 한다 | [측정] |
| BAL-6 | **계약 목표가 경쟁을 모른다.** "서울⇄도쿄 6개월 승객 123,000명"처럼 점유율이 떨어진 노선에 지금 실적의 1.15배를 요구해 실패한다 | [측정] 실패 사례 1건 |
| BAL-7 | 대형 사업은 월 납입이 크다(항공 학교 월 $5M). 초중반 이익(월 $1~2M)으로는 공사가 계속 멈춘다. 착공 전에 "지금 월 이익으로 감당 가능한지"를 알려 줘야 한다 | [측정] |
| BAL-8 | 자동 전략은 운수권이 있으면 노선 2개에서 더 못 늘린다. 전략의 한계라 사람 난이도의 증거는 아니다. **사람 기준 난이도는 여전히 미확인** | [측정] / 한계 |

## 6. 권하는 순서

1. **BUG-1~4**(데이터가 어긋나는 버그) → BUG-5~7(눈에 보이는 버그)
2. **BAL-1·2·4** 조정과 재측정. 자유 모드의 재미를 가장 크게 좌우한다
3. **UX-1·2·3**(결정할 것 모으기, 팝업 통일, 이익 표시 통일)
4. PERF-1 측정 → 필요하면 최적화
5. 나머지 UX·GFX

## 측정 방법 (다시 돌릴 때)

`airline/tests`에 임시 테스트를 만들어 `new Game(seed, undefined, { sandbox: true, rights: true })`에 `featured('all', { upgrades, hubs, contracts, newgen, auction, rights })` 전략을 120개월 돌리고, 36개월마다 현금·월 이익·내 항공기 수·경쟁사별 항공기 수·첫 노선의 점유율을 적는다. 시드 1~4. 이야기는 마지막 선택지(돈이 안 드는 쪽)를 고르고 대형 사업은 시작하지 않는다(시작하면 월 납입 때문에 파산해 비교가 흐려진다). 임시 테스트는 커밋하지 않는다.

기준값(2.6.0, 시드 1 / 2 / 4, 108개월차): 내 항공기 3 / 4 / 3대, 경쟁사 최대 28대, 서울⇄도쿄 점유율 10%. 시드 3은 26개월에 파산.
